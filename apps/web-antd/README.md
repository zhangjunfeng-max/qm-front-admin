# 团购营销管理端（Ant Design Vue）

本应用对接 `group-biz`，使用 Vben 的布局、表单、路由和 Pinia，业务组件使用 Ant Design Vue。登录只输入手机号和密码；一个有效公司直接进入首页，多个公司在登录面板选择，进入后可从顶部切换。

AI 开发约定见仓库根目录的 [AGENTS.md](../../AGENTS.md)。新增或修改业务列表页时，遵循其中的字段展示、列表高度、滚动和底部分页规范。

## 本地启动

在仓库根目录运行：

```sh
pnpm install
pnpm dev:antd
```

访问 `http://localhost:5666` 或局域网地址，例如 `http://192.168.5.22:5666`。开发环境已关闭 Nitro Mock，浏览器请求 `/api/v1`，Vite 将 `/api` 原样代理到 `http://127.0.0.1:8080`。先启动 `group-biz` 和本地 MySQL、Redis。

浏览器向 Vite 发送的是同源请求，开发代理会移除发往后端的 `Origin`，因此更换局域网 IP 无需修改后端 CORS。修改代理配置后需等待 Vite 自动重启，或重新运行 `pnpm dev:antd`。直接访问后端 API 或生产环境跨域请求仍需配置后端 `CORS_ALLOWED_ORIGINS`。

## 当前接口

| 功能         | 接口                                                        |
| ------------ | ----------------------------------------------------------- |
| 获取登录公钥 | `GET /api/v1/auth/public-key`                               |
| 登录         | `POST /api/v1/auth/login`                                   |
| 选择公司 | `POST /api/v1/auth/select-tenant`，提交短期选择凭证与目标公司 |
| 本人公司列表 | `GET /api/v1/auth/tenants`，普通用户返回本人有效公司，平台管理员返回全部公司 |
| 切换公司 | `POST /api/v1/auth/switch-tenant`，提交当前刷新令牌和目标公司 |
| 租户资料 | `GET/PUT /api/v1/platform/tenants/:id`，平台专属 |
| 自动刷新     | `POST /api/v1/auth/refresh`，JSON 提交刷新令牌              |
| 登出         | `POST /api/v1/auth/logout`，Bearer 访问令牌 + JSON 刷新令牌 |
| 重载校验身份 | `GET /api/v1/auth/me`                                       |
| 平台租户列表 | `GET /api/v1/platform/tenants`，仅平台管理员，服务端分页 |
| 当前租户     | `GET /api/v1/admin/tenant`                                  |
| 当前租户成员 | `GET /api/v1/admin/members`                                 |

登录时每次先取公钥和 120 秒一次性挑战，再用 RSA-OAEP/SHA-256 加密密码，提交 `phone`、`encryptedPassword`、`keyId`、`challenge`。OAEP label 为 `["group-biz/login/v2", keyId, challenge, phone]` 的紧凑 JSON UTF-8 字节。使用 `node-forge` 兼容局域网 HTTP；生产环境仍需 HTTPS，私钥通过后端 `LOGIN_RSA_PRIVATE_KEY` 注入，前端只持有公钥。新数据库执行后端 `000001_init` 基线迁移。

后端成功响应直接返回 JSON，不使用模板的 `{ code, data }` 包装。没有 `/auth/codes`、`/user/info` 或后端菜单请求；菜单使用已验证身份中的角色生成，API 权限仍由后端强制校验。

所有账号完成公司选择后统一进入首页（`/home`），不按角色跳转到不同页面，也不恢复旧 redirect 指定的页面。首页按权限展示：owner/admin 在首页查看和编辑**当前公司资料**，member 查看本人账号信息，且不请求公司管理接口。人员统一在“员工管理”查看和维护，支持服务端分页、搜索和筛选。平台“租户管理”是独立的 `/platform/tenants` 页面，查询所有公司，支持服务端分页、公司公司名称搜索和状态筛选；仅 `isPlatformAdmin` 为真的账号可见，后端实时校验独立授权。租户资料支持详情与编辑，包含联系人、电话、行业、地址、服务到期时间和备注；列表还显示有效成员数，并可创建租户及其初始所有者。

平台管理员和公司 `owner/admin/member` 使用相同登录流程，单公司直接进入首页，多公司先选择。原 `/tenant` 地址重定向到 `/home`。平台管理员通过“租户管理”菜单进入 `/platform/tenants`，平台权限与公司的 owner/admin 权限分开。平台权限由后端 `go run ./cmd/platform-admin -phone <手机号>` 运维命令授予，添加 `-revoke` 撤销；demo 默认仍是公司 owner。模板的演示菜单不加入业务路由。

## 公司选择与切换

密码验证成功且绑定多个有效公司时，原登录面板切换为公司列表，展示姓名、公司、公司内角色与上次进入时间，支持搜索和更换账号；此时尚未保存业务访问令牌。选择凭证仅在内存保留 5 分钟，刷新页面后需要重新验证密码。仅绑定一个有效公司时不展示选择步骤。

左侧菜单按当前工作范围生成：平台管理只显示租户管理、用户管理；选择公司后只显示该公司角色可用的业务菜单。平台管理员通过顶部“平台管理”切回平台范围。

Header 常驻当前公司入口，普通用户只能选择本人有效成员关系中的公司，平台管理员可选择全部公司。选择后仅查询当前公司的业务数据。切换前刷新凭证，重新签发目标公司的身份，清除权限、标签页与页面缓存后进入首页；其他标签页收到通知也会重载。服务已到期、租户禁用或成员已禁用的公司不能进入。刷新页面通过 `/auth/me` 恢复真实姓名、角色与公司名称。切换开始即卸载旧页面并禁止业务请求，取消在途请求和素材上传；每次上下文变更使旧响应、旧表单上传和旧权限生成结果失效，即使 A→B→A 也不复用旧结果。跨窗口切换会同步清除状态，休眠窗口发请求前校验上下文标记；浏览器历史缓存恢复时重新加载身份。

新数据库执行后端 `make migrate-up` 创建 `000001_init` 完整结构，再启动服务；登录只提交手机号及认证信息。

## 活动、员工与分组管理

在 `group-biz` 执行 `make migrate-up` 创建完整基线后，可使用以下管理页面。后端说明见相邻 `group-biz/docs/activity-management.md`。

| 页面 | 范围 |
| --- | --- |
| `/activities` | 当前租户活动的服务端分页、搜索、创建、编辑、归档和恢复 |
| `/activities/:id` | 活动员工指定、角色调整、加入申请审核、活动内分组及渠道内员工邀请 |
| `/employees` | 当前租户员工的分页、搜索、创建、编辑和禁用，租户 owner/admin 可用 |
| `/stores` | 当前租户门店分页、搜索、新增、编辑及启用停用，活动支持多选关联 |
| `/home` | 首页公司资料编辑，租户 owner/admin 可用；其他账号查看本人信息 |

活动配置包含名称、海报、规则、时间、详情图片/视频顺序、拼团人数及价格、单买价格、分享与转发素材、背景音乐、虚拟浏览量、员工范围、业绩可见范围、活动参与门店和客服电话优先顺序。金额在界面以元输入，接口使用整数分；未设置单买价格表示不开放单买。图片、详情视频和音乐使用上传组件，先本地暂存和预览，保存活动时上传，未变更文件不重复上传。详情使用有序的 detailMedia（{type: image/video, url}），支持图片/视频混排拖动排序（最多50项）和视频弹窗播放。图片使用开源 browser-image-compression 进行手机浏览优化：宽度最多1440px、长图等比缩放，85%初始画质，最多4轮调整且不再缩小分辨率，尽量压至400KB；JPG保持JPEG，静态PNG/WebP优先输出支持透明的WebP，动画保留原文件，处理结果更大则保留原图。压缩后图片最大4MB，超出拒绝暂存及上传；音乐最大10MB，MP4/WebM 视频原文件上传、最大50MB。动态表单固定包含必填客户姓名、手机号，其余字段可配置文本、长文本、日期、电话、邮箱、单选、多选和是否；单选/多选可维护选项。

门店由租户 owner/admin 在门店管理中维护；保存活动后，在「详情 → 参与门店」独立配置参与门店，可多选或留空。新选择限启用门店，原有停用门店保留回显并可移除，保存时后端校验租户归属。

客服电话优先顺序默认“联系销售→联系门店→联系公司”，可拖动或使用前移/后移按钮调整并保存。后续客户端依次查找可用电话号码，本期仅管理配置。

指定活动员工：保存活动后，进入「详情 → 活动员工与申请 → 批量添加员工」，支持搜索、跨页勾选和表头全选当前页，每次最多1000人。候选列表只返回尚未加入当前活动的有效员工，已有活动记录（含待审核、驳回、停用）均过滤；分页和总数按过滤后的结果计算。支持批量调整角色/小组、启用/停用和审核。活动门店支持多选、全选和清空，最多500家。

员工归属租户，分组和活动角色归属具体活动，同一员工在不同活动可有不同分组和角色。活动角色为组员、组长、活动管理员，区别于公司的 owner/admin/member。组员业绩可见范围为本人、本组或活动全部员工；组长为本组或活动全部员工；活动管理员为当前活动全部员工。本期仅配置权限范围，不展示业绩数据。组长只能审核本组的组员申请；活动管理员管理组员和组长；公司管理员管理全部活动角色。

邀请二维码指向员工加入管理入口，包含邀请令牌；重置邀请后旧链接失效。已有账号验证原密码，新账号创建员工并提交待审核申请，申请角色须经审核才生效。公开注册密码沿用 RSA-OAEP 加密协议。禁用员工、失效邀请及跨租户访问由后端校验。

活动按草稿、审核中、审核通过/未通过、发布、进行中、已结束流转，平台审核通过后由公司发布；支持归档。支付退款、在线活动计费和赠送次数尚未接入。

活动详情“活动推广”和“员工邀请”都严格跟随活动渠道，同一活动只生成一套渠道入口。H5 活动生成 H5 链接和普通二维码，小程序活动生成小程序码；员工邀请进入移动端 `/pages/staff-invite/index`，不再使用管理端账号密码表单。H5 地址通过 `.env.development` / `.env.production` 的 `VITE_ACTIVITY_H5_URL` 配置。关闭弹窗、切换活动或公司时取消请求并清空素材，旧响应不能覆盖当前活动。

## 会话行为

- 普通请求使用 Bearer access token。认证中间件返回 `401` 后，复用同一刷新 Promise，成功时一起更新两枚令牌，重发原请求一次。
- 登录、刷新、登出使用独立请求客户端，避免刷新循环；`403` 不触发刷新。
- 刷新返回 `401` 清除会话并回登录页；`503` 或网络故障保留凭证，一秒后重试一次。响应丢失时可利用后端 30 秒幂等窗口。
- 已有较新访问令牌时，迟到的 `401` 直接使用新令牌。支持 Web Locks 的浏览器在轮换期间协调同源标签页；不支持时使用当前页并发合并和后端短时幂等保护。
- 登出先清除本地会话，防止进行中的刷新恢复登录，再向后端撤销所持令牌。访问令牌已过期时，仅为撤销会话轮换一次并立即登出，不恢复本地登录态。
- 默认访问令牌 15 分钟、刷新令牌 30 天；闲置期间不定时刷新，下次请求时续登录。

## 客户与活动订单

公司负责人、管理员、活动组长和活动管理员可进入“客户管理”（`/customers`）和“活动订单”（`/orders`）；普通组员从活动详情的“订单管理”进入。数据按各活动配置的全部、本组、本人权限过滤。支持姓名、手机号、活动、销售、订单号和状态筛选，优先展示支付状态、姓名电话、销售、报名成功/订单创建/留资时间；待支付突出展示。未登录填写姓名电话后即建档并展示待报名记录，没有订单号和金额；正式报名后关联订单且不重复展示。客户行可一键查看待报名、待支付及完整回答。虚拟素材不进入后台，页面沿用公司隔离与切换清理。

公司客户档案按公司和手机号留存，可关联多次活动；不同活动分别保存订单，订单不合并。登录身份与客户联系档案分开，填写手机号不能当作身份验证；跨公司同手机号不冲突，资料和订单独立。接口及隔离规则见后端 `docs/customer-order-management.md`。

订单号使用 `orderNo` 字符串，格式为北京时间14位年月日时分秒加6位全局序列（共20位纯数字），由 Redis 原子生成、数据库唯一约束保证不重复。订单列表、详情及搜索均使用该业务号码；内部 UUID 只用于主键、行标识和请求参数，不能把20位订单号转换成 JavaScript Number。

## 验证

```sh
pnpm --filter @vben/web-antd typecheck
pnpm --filter @vben/web-antd build
pnpm exec vitest run apps/web-antd/src/api/__tests__
```

生产环境默认请求同源 `/api/v1`，需要网关将该路径转发到后端。部署到独立 API 域名时修改 `.env.production` 的 `VITE_GLOB_API_URL`，并配置后端 HTTPS CORS 来源；History 路由需为前端路由配置 `index.html` 回退。

活动图片和背景音乐复用上传组件：选择后只在本地处理、预览，点击保存活动才上传；编辑未更换的素材不重复上传，失败重试复用已成功上传的文件。详情图支持拖动排序。图片使用开源 `browser-image-compression` 优化尺寸和画质，按宽度等比缩放以保留长海报，尽量压至400KB，以4MB作为压缩后上传硬上限；仅平台级用户显示文件大小及原始/处理后大小提示，租户内所有用户隐藏；素材卡片用橙色状态点表示待保存、绿色表示已上传，悬停查看状态。随活动保存原始及实际字节数，以及实际输出的文件名和MIME类型。预览使用后端签发的私有 COS 短时 GET URL，活动保存无签名文件 URL。开发环境必须先配置 COS 及其 PUT/GET CORS，未配置时上传如实提示失败，不会假装保存成功。
